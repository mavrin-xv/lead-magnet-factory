# How it works

The pack splits a lead magnet into five jobs. Each job has one skill, one file it writes and one script that checks it. The model does the judgement work; the scripts do the counting, so the same mistakes are caught every time.

```
 raw input                survey answers
 (article, voice note,    (CSV export)
  research, topic)             |
        |                survey-to-magnet ---- cluster_survey.py
        |                      | survey-outline.md
        v                      v
   magnet-concept ------------------------ score_concepts.py
        | concept.md (reader, pain, offer, bridge, title, quick win)
        v
   magnet-writer ------------------------- magnet_lint.py
        | magnet.md  --> md_to_html.py   --> magnet.html
        |            --> md_to_notion.py --> Notion page
        v
   keyword-delivery ---------------------- flow_builder.py
        | flow.json --> flow.md (trigger, messages, tagged links, test plan)
        v
   magnet-promo -------------------------- promo_check.py
          promo.md (one post per platform) + launch checklist
```

## Why five skills and not one

A single "write me a lead magnet" prompt makes four decisions at once: what to give away, how to write it, how it is delivered and how it is announced. When the result is weak you cannot tell which decision was wrong. Split, each one can be checked and redone on its own. You can also start in the middle: if you already know what the magnet is, go straight to `magnet-writer`.

## What the model decides, what the scripts check

| Job | The model decides | The script checks |
|---|---|---|
| Survey | Theme names, which quotes are telling | Clusters by shared words, counts, depth, intent words, ranking |
| Concept | The reader, the bridge to the offer, scores 1 to 5 | Rejects any test below 3, doubles bridge and value, ranks |
| Writing | Every word, the structure, the quick win | Item counts per format, paragraph length, placeholders, the Next step section, the keyword |
| Delivery | The messages and their tone | Keyword shape, reply length, link placement, button label, disclosure, follow-up window |
| Promo | The angle per platform, the give-away item | Length limits, keyword present and near the end, link rules per platform, one call to action |

## Files per magnet

Work happens in `magnets/<slug>/` in your project:

```
magnets/dial-in-checklist/
  concept.md          from magnet-concept
  magnet.md           from magnet-writer (source of truth)
  magnet.html         generated
  magnet.notion.json  generated by the dry run
  flow.json           from keyword-delivery
  flow.md             generated
  promo.md            from magnet-promo
```

Edit `magnet.md`, then regenerate the HTML and Notion page. Never edit the generated files by hand: the next run overwrites them.

## What leaves your machine

Nothing, unless you run `md_to_notion.py --push`. That sends the page to the Notion API with the token in `NOTION_TOKEN`. No script posts to social platforms or sends messages; `flow.md` is a sheet you copy into your DM tool by hand.

## Worked example

`examples/acme-coffee/` runs the whole chain for an invented coffee roaster: a voice note and 24 survey answers in, a 22-point checklist, its delivery flow and eight promo posts out.
